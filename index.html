    What is included?

    All detected entries are retained, including duplicate and unknown frames. Binary or encrypted fields remain available as bytes. Original tag blocks can be downloaded from each tag section.

    Format support & limitations

    Reads ID3v2.2–2.4 (including text encodings, unsynchronisation, common binary frames and chapters), ID3v1/v1.1 and TAG+, APEv1/v2, and Lyrics3v1/v2 at standard tag locations. Unrecognized ID3 frames and APE binary values have a raw view. Encrypted frames are not decrypted. Compressed ID3v2.3/2.4 frames are decoded when the browser supports DecompressionStream. Whole-tag ID3v2.2 compression is undefined and is kept as raw data.

    To keep the browser responsive, at most 64 MiB of stored tag data is decoded per inspection, with 20,000 entries and eight chapter nesting levels. Decompressed payloads share a separate 64 MiB budget. Tags over the limit remain downloadable in full. Hex views are paged; JSON includes every parsed payload as Base64. Audio properties come from MPEG and Xing/Info/VBRI headers; duration is an estimate when no frame count exists. No full audio-stream validation is performed. ID3v1 uses Latin-1; tags saved using a different legacy code page may display differently.

    Editing supports ID3v2.2–2.4, APEv1/v2 and ID3v1/v1.1 text fields. ID3v2 and APE artwork can be replaced or removed. Choose the tag block you want to change; separate copies in other tag blocks are independent. New ID3v2 tags use version 2.3. Untouched frames and other tag blocks are retained. Optional ID3 extended headers, including their CRC and restrictions, are omitted when a tag is rebuilt. Malformed or partially decoded tag structures remain inspection-only. Files with chapter byte offsets or position-dependent tags can be edited only when tag size stays the same. Saving downloads a new MP3 without re-encoding audio.
